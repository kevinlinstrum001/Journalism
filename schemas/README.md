# Schemas

## Purpose

This directory is reserved for machine-readable structural definitions used by Journalism records, sidecars, catalogs, and tools.

Schemas should be introduced only when an actual record family has been used enough to justify a stable structure. The repository should not accumulate speculative schemas merely because a concept exists.

## Principles

- Define semantics before field names.
- Keep stable identity separate from name, location, status, hierarchy, and implementation.
- Make authority boundaries explicit.
- Preserve unknown, provisional, disputed, historical, and verified states where relevant.
- Version schemas when compatibility matters.
- Prefer validation rules that protect meaning rather than merely enforcing formatting.

Draft schemas should identify themselves as drafts until tested against real records.
